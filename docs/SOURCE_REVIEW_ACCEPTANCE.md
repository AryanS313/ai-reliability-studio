# Source-review acceptance matrix

This matrix applies to teams checking support or RAG assistant answers against supplied source documents. The product must preserve the evidence, make uncertainty visible, keep decisions attached to the exact evidence reviewed, and compare replacements without implying that an automatic score proves correctness.

Reviewed baseline: commit `f113ce17dc9924fff300a8d91ab3814be8bfbd98`. The repairs below are subsequent working-tree changes for release `2026.09.08.1`; this document alone does not establish their publication or hosted acceptance. The new fixtures are authored software regression cases, not human calibration or an unseen model-quality benchmark.

## Acceptance criteria and evidence

| Workflow requirement | Concrete acceptance criterion | Evidence and scope |
| --- | --- | --- |
| Plain text and Markdown | Retain policy text, punctuation and Unicode. UTF-8/BOM, UTF-16 with BOM and supported Latin-1 text must not silently become unrelated glyphs. Preserve Markdown sections. | New text-fidelity cases and existing structural chunking test pass. BOM-less UTF-16 is not an established input format. |
| Word policy tables | Preserve the order of body paragraphs and tables and attach a table to its actual preceding heading. Moving an identical table to a different policy section must change the extracted source identity. | Two new DOCX regressions pass after the loader repair. Scope: ordinary body paragraphs, headings and top-level tables, using the pinned python-docx package. |
| Tabular source values | Preserve literal text such as `001`, `NA`, `NULL` and `1.00` in representative CSV/TSV tables and text-valued Excel cells. | Three new source-table regressions pass. This does not promise preservation of spreadsheet display formats, formula calculation, merged-cell layout or every spreadsheet feature. |
| Question/answer alignment | A question ID such as `001` must remain the same ID when imported from CSV or JSON and joined with saved CSV answers. Literal expected-answer/source strings must remain strings. | Two new question/response cases pass after the dataset-reader repair. Existing saved-response tests reject missing, extra and duplicate response IDs. |
| Structured source JSON | Preserve passage text, IDs, section metadata and declared document versions. Importing a declaration must not authenticate its origin. | New JSON round-trip case passes; existing source and manifest tests cover version-bound evidence. |
| Searchable PDF and extraction notices | Preserve representative searchable table text and page numbers. A page without searchable text must produce an explicit extraction notice; retain that notice through saved and live source chunking, content deduplication and workspace export/restore. | New PDF/parser, shared chunking and source-workspace cases pass. A blank page is not proof that policy content is missing. The UI/reports must display retained notices; their visual acceptance and persistence through database reload are verified separately by their owners. |
| Reviewable chunks | Retain row newlines, tabs and Unicode whitespace inside each chunk. Every character span must reproduce the exact chunk text, with unchanged word-window and overlap counts. | Seven new chunk/span cases pass, including repeated words, zero overlap and high overlap. Auxiliary metadata cannot replace generated text or spans. |
| Interpretable locations | Map structural blocks to document coordinates only when their literal text is present. Otherwise label coordinates as block-relative and retain `block_index`; never invent a document offset. | New document-coordinate and explicit block-coordinate cases pass. `text_span_scope` describes coordinates in extracted text, not byte offsets in the original PDF/DOCX file. |
| Source-bound review decisions | Changed answers, expectations or source snapshots invalidate prior reviews. Source differences or unreviewed replacements cannot be called resolved improvements. | Existing [saved-response tests](../tests/test_saved_responses.py) cover all three review hashes, pending states, partial retests and non-comparable source versions. These contracts are separate from deciding whether a reviewer's judgment is correct. |
| Contradiction, unsupported claims and uncertainty | Established citation/claim defects must remain failures; unfamiliar or unverified support must remain unresolved without fabricated certainty. Automatic outcomes must remain separate from explicit reviews. | Existing [citation tests](../tests/test_scoring_citation_uncertainty.py), [constraint tests](../tests/test_scoring_constraint_preservation.py) and [report contract tests](../tests/test_reporting_contract.py) cover these distinctions. This bounded source repair does not claim new general accuracy. Every imported answer still needs review. |
| No unsupported launch claim | Imported answers and fictional executions must receive no launch verdict. High scores cannot override unresolved determinations or absent qualifying calibration. | Existing [aggregation tests](../tests/test_aggregation.py) and replay/report tests cover these gates and evidence banners. An offline source review does not establish live retrieval, account access or production readiness. |
| Honest handover | A restored workspace must retain source warnings, evidence, reviewer attribution and pending decisions. Reports must distinguish declared source review from automatic checks and unknown client measurements. | New warning-preservation cases plus existing workspace/report contracts. Browser download completion and current hosted UI behavior remain separate acceptance checks; a parser test cannot establish them. |

## Reproduced defects and repairs

The initial new source-input selection produced **8 failures and 4 passes**. It exposed: DOCX tables moved after all paragraphs and assigned the final heading; identical hashes when moving a table between sections; numeric/NA inference corrupting tabular source values; Latin-1 text guessed as UTF-16; and question IDs converted to numbers while answer-file IDs remained strings. Each has a focused regression case. Saved and live source paths also discarded PDF extraction notices when converting documents into chunks; notices now travel through the shared document layer into the reference packet, including warnings from content-deduplicated documents. The bounded helper is shared by import, evaluation and reporting rather than owned by the UI.

All **7 initial chunk/span cases failed**. Normalizing whitespace erased table rows, approximate offsets did not reproduce the quoted text, coordinate scope was unspecified, and auxiliary metadata could overwrite derived text/spans. Chunking now slices original text using token boundaries. Word-window size and overlap policy are unchanged. A source snapshot can change when the recovered text or its provenance changes, so earlier reviews must be reapplied only if their existing hashes still match.

Current focused native verification: **39 tests passed**—27 new source/chunk cases plus 12 existing document/retrieval cases. Four additional cases cover plain and structured live chunks, duplicate-document warnings, and the shared document/UI helper contract. Ruff, formatting, type checks for the three changed helper/loader/chunker modules and diff checks passed. The protected runner blocked external calls and secret reads. Full native regression, WebAssembly runtime checks and deployed acceptance belong to the release evidence, not this focused count.

New regression files: [source input fidelity](../tests/test_source_input_fidelity.py) and [chunk source spans](../tests/test_chunk_source_spans.py).

## Remaining boundaries

These examples do not certify faithful extraction of every PDF or Word layout. Complex PDF reading order, raster content on otherwise searchable pages, Word headers/footers, nested objects and advanced tables require separate representative checks or an operator-verified text/passages export. The current tests do not establish their completeness. Source hashing binds the extracted reference packet, not authenticity or complete original-file coverage.

The review workflow also needs authoritative source versions, representative cases and a person responsible for resolving policy ambiguity. Finite software tests and scripted examples cannot establish an assistant's accuracy across a team's workload. The useful supported claim is that the app preserves and organizes a bounded source review and its retest evidence; automatic findings remain advisory.
